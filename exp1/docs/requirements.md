## 2. 数学定义与参数

位从左侧开始按 1 编号。对置换表 `(a1,...,am)`，输出第 j 位取输入第 `aj` 位。明文、密文为 8 位；主密钥为 10 位；两个子密钥均为 8 位。

```text
P10    = (3,5,2,7,4,10,1,9,8,6)
P8     = (6,3,7,4,8,5,10,9)
IP     = (2,6,3,1,4,8,5,7)
IP^-1  = (4,1,3,5,7,2,8,6)
EP     = (4,1,2,3,2,3,4,1)
P4     = (2,4,3,1)
```

以上参数已对石墨正文、公式和图示逐项读取并视觉核对。源文中四位置换标为 `SPBox=(2,4,3,1)`，本项目将其命名为 `P4`；源文图示的输出位置也是 `2,4,3,1`。

作业给出的两个 S 盒如下，元素是十进制数，查表后输出两位二进制数。不能直接采用其他教材中同名 S 盒；作业特别提醒 S-box2 曾作修改，跨组互测时必须确认参数一致。

```text
SBOX1 = ((1,0,3,2),
         (3,2,1,0),
         (0,2,1,3),
         (3,1,0,2))

SBOX2 = ((0,1,2,3),
         (2,3,1,0),
         (3,0,1,2),
         (2,1,0,3))
```

4 位输入 `b1 b2 b3 b4` 的 S 盒行号是二进制 `b1 b4`，列号是二进制 `b2 b3`，行列均从 0 开始。

```text
F(R,Ki) = P4(SBOX1(X[1..4]) || SBOX2(X[5..8]))
X       = EP(R) xor Ki
fKi(L||R) = (L xor F(R,Ki)) || R
SW(L||R)  = R || L

E_K(P) = IP^-1(fK2(SW(fK1(IP(P)))))
D_K(C) = IP^-1(fK1(SW(fK2(IP(C)))))
```

第二轮后不再交换两个半块。解密使用相同网络，子密钥次序为 K2、K1。

### 密钥调度的两种解释

石墨公式为 `k_i = P8(Shift^i(P10(K))), i=1,2`，并分别定义 5 位半块的置换：

```text
Shift^1 = (2,3,4,5,1)
Shift^2 = (3,4,5,1,2)
```

`P10(K)` 分成两个 5 位半块后，默认按公式字面含义从同一原始状态分别左移 1 位、2 位。课件常见流程是先左移 1 位取得 K1，再继续左移 2 位取得 K2，第二轮相对原始状态总左移 3 位。两者不能混用。

| `schedule` | K1 相对 P10 的总左移 | K2 相对 P10 的总左移 | 角色 |
|---|---:|---:|---|
| `assignment` | 1 | 2 | 默认；主实验按作业公式字面解释 |
| `cumulative` | 1 | 3 | 显式的课件兼容选项 |

GUI、CLI、ASCII、攻击和碰撞分析都使用同一所选调度。输出报告必须记录调度；两个模式的密文不能当作相同算法条件的结果比较。

## 3. 五关功能与验收

### 第一关：基本测试

GUI 接受 8 位二进制明文/密文和 10 位二进制密钥，执行加密与解密，显示 8 位结果。错误位宽、非二进制字符和无效密钥应提示错误。前导零必须保留。

验收证据包括加密、解密界面截图、可人工复核的中间过程、往返测试，以及全部 `1024 × 256` 个主模式密钥/明文组合的验证。每个固定密钥应在 256 个明文上形成一个双射。

### 第二关：交叉测试

与另一组使用不同语言或平台的程序交换输入输出：A 组加密结果交给 B 组解密，相同输入和同步后的参数应给出相同结果。互测前确认置换表、S 盒（尤其 SBOX2）、位序、密钥调度与密文表示。

本项目提供独立的位串参考实现、JSON/CSV 交换向量和比较脚本。目前的结果是**本地两份独立实现交叉验证**；没有收到另一组的程序或真实互测结果，不能据此宣称完成跨组、异构平台互测。正式提交前需补充另一组身份、平台、真实交换数据及比较记录。

### 第三关：扩展功能

接受 ASCII 字符串，将每个字符的 8 位字节独立加密/解密。ASCII 范围为 0–127，非 ASCII 字符应拒绝。空串和控制字符在核心 API 中保留。

加密字节可能不是可打印字符，因此 GUI/CLI 使用 Hex 或 Base64 保存、展示和输入密文；解密还原 ASCII。两种表示不会改变密文字节，也不替代加密。TCP 传输只是作业的可选应用示例，不是必需功能。

验收包括正常字符串、空串、0–127 全 ASCII、0–255 全字节的往返测试，以及 GUI 的 Hex/Base64 演示和非 ASCII 错误提示。

### 第四关：暴力破解

支持一个或多个已知的 `(明文,密文)` 对，枚举全部 1024 个 10 位密钥，输出同时满足所有输入对的**全部候选密钥**。不在首次命中后停止，不把多个候选误报为唯一恢复。空输入应拒绝；不相容的输入应返回零候选。

显示真实开始/结束时间戳和实测耗时；时间戳包含时区，耗时由单调时钟 `perf_counter()` 计算。GUI 提供真实检查进度，并以视频或 GIF 动态演示运行。线程是作业允许的实现选择；本项目使用 QThread 后台计算。

验收比较单对和多对输入的候选变化，并记录原密钥是否在候选中。若调度本身存在全局等价密钥，必须说明不能唯一识别的原因。

### 第五关：封闭测试与碰撞分析

固定一个 8 位明文，逐一使用全部 1024 个密钥加密，按相同密文分组并给出每组所有密钥，分析不同密钥产生相同密文的情况。进一步扫描所有 256 个明文，并区分“在某个明文上碰撞”与“对全部明文完全等价”。

全局等价判定使用完整的 256 项加密置换；仅凭单个明文的相同密文不能判定等价。验收保存完整映射、分桶统计、碰撞例子与区分非等价密钥的反例。默认调度下的结果还需结合密钥调度分析有效密钥空间。

## 4. 实现质量与边界

函数、变量和模块命名清楚；重要位操作、调度歧义与查表优化有注释。核心函数封装可复用，GUI/CLI 调用同一核心，核心与攻击模块只依赖标准库，不调用现成密码库。PyQt5 用于 GUI；Pillow 仅用于截图/GIF 证据生成。

本实验不扩展为真实密码系统。逐字节独立模式、8 位分组和 10 位主密钥均服务于教学分析。界面和 API 不提供随机化模式、完整性认证或密钥管理。
